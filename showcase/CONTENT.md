# Adding content to the showcase (for any Claude chat, or anyone with the repo)

The showcase is built from one data file, `content/events.json`: every event (title, text, services, event types, English and Arabic) and every clip (photo or video) in it. The media itself lives in `media/`. Nothing else needs editing by hand.

## The 3-step flow
1. **Put the new files in a folder** (photos: jpg/png/heic, videos: mp4/mov). Do not compress them first, the tool does it.
2. **Add them**, from the repo root:
   ```
   python3 -I showcase/build/add_content.py --src /path/to/folder --event <event-slug> --svc laser,lighting
   ```
   - `--event` is an existing slug (see `content/events.json`, or `COVERAGE.csv`). Add `--star` to make clips hero shots.
   - Several events at once: write a `manifest.csv` with columns `file,event,svc,star` and pass `--manifest manifest.csv`.
   - A long promo that should play whole: add `--film` (one film per event, up to 170 s, must end up under 20 MB).
   - A brand-new event: add `--new-event --title "…" --dek "…" --desc "…" --body "…" --types wedding --city "Abu Dhabi" --venue "…" --month 2026-10 --event-svc lighting` plus the four `--ar-title/--ar-dek/--ar-desc/--ar-body` Arabic texts (the Arabic page needs them).
   - Exact duplicates are skipped automatically (file hash).
3. **Publish**: `python3 -I showcase/build/release.py`. It commits the media, pins the CDN link to that commit, rebuilds the English and Arabic blocks, pushes, and prints what to paste into Squarespace (replace the Code Block with the new `showcase/embed/showcase-en.html`, and `-ar` for the Arabic page).

## Rules that keep the page honest
- **Services**: `lighting` (stage and architectural lighting), `led` (LED screens), `sound`, `mapping` (real 3D/projection mapping only), `laser` (lasers, sky beams, cold sparks). A clip's service must be one of its event's services. Sound is implied for every event. Do not tag a laser clip as lighting or a projection as mapping unless it is.
- **Event types**: corporate, gala, wedding, launch, government, private, exhibition, show.
- **Client names** appear only where the owner put them in a title or ticked "OK to show". When in doubt, leave the name out.
- **Never invent facts** (guest counts, results). Text uses only what the owner gave: venue, city, month, what was delivered.
- **Nothing silently dropped**: `COVERAGE.csv` lists every original file as "on the site" or "skipped" with the reason. Add a row there for new files if you want the record to stay complete.

## Where things are
| Path | What |
|---|---|
| `content/events.json` | all events and clips (the source of truth) |
| `media/i`, `media/v` | web-sized photos and videos (+ poster jpgs) |
| `embed/` | the generated Squarespace blocks and loaders |
| `build/` | the scripts (`add_content.py`, `release.py`, `build_embed.py`) |
| `SEO-PACK-EN.csv`, `SEO-PACK-AR.csv`, `SEO-ALT-TEXT.csv` | regenerated by every build |

## For the owner (no coding)
Open a new Claude Code chat on this repo and say: *"Read showcase/CONTENT.md. Add the photos and videos from <link or folder> to <event>. Then publish."* The chat does steps 1 to 3. You then paste the new block into Squarespace.
